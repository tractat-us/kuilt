# `:kuilt-heddle` — implementation plan

Execution plan for the weighted fair-share scheduler designed in
[`docs/heddle-design.md`](../heddle-design.md). The design doc is normative; this
doc is the *build order* — how the phases become sub-issues, what gates what, how
workers are dispatched, and where the risk sits. Read the design doc first.

## Goal

Ship `:kuilt-heddle` — a standalone module giving kuilt hierarchical, weighted,
partition-tolerant fair-share scheduling — and land it as warp's missing
apportionment layer. The whole thing is a *thin reframing* over primitives kuilt
already ships; the only genuinely new code is the `EntitlementLedger` CRDT, a
tiny lifecycle max-register, and the pure EEVDF policy (design §12).

## The build DAG

The phases form a DAG — mostly a chain, with one real parallel branch — and a
landed phase's review/hardening can overlap the next phase's implementation.

```text
H1a ─▶ H1b ─▶ [spec-conformance gate] ─┬─▶ H2 ─┐
                                        └─▶ H3 ─┴─▶ H4 ─▶ H5 ─▶ H6 ─▶ H7
```

- **H1a → H1b**: the ledger splits into a merging-but-inert lattice (H1a) and the
  entitlement economics on top of it (H1b). H1b is where a conservation bug would
  live, so the spec-conformance gate sits immediately after it (see below).
- **H2 ∥ H3**: once H1 lands, the pure policy (H3) and the topology lifecycle (H2)
  proceed in parallel — near-zero file overlap, neither consumes the other's
  output. **Condition:** H3's inputs (`EdgeSummary` + attachment metadata + the
  `Demand` type) must all belong to H1, not H4 — see H3 below. H4 is the join.
- **H5 and H6 can overlap.** Every H6 acceptance criterion is satisfiable with the
  `heddleStatic` bootstrap (no Raft mint needed), so H6 does not strictly wait on
  H5 — sequence them only to the extent reviewer bandwidth demands.

Everything through H5 lives in `:kuilt-heddle`; H6 is a new small warp satellite.

## Review gates (spec-critical, per CLAUDE.md)

This module implements a formal fairness/conservation model, so behavior-preserving
review is not enough — the new units get audited against the *spec* (design §4/§10
as normative text), treating a passing property suite as necessary but not
sufficient. Three gates:

1. **After H1b — ledger spec-conformance review (opus).** Audit `EntitlementLedger`
   against design §4 and invariants §10.1–3/8/12 *before* H2/H3/H4 build on it. This
   is the maximum-leverage point: a §4 exclusive-slot or conservation bug found here
   costs one phase, not three. (The repo's own receipt: the `RaftEngine` decomposition
   found ~18 pre-existing bugs the behavior reviews passed.)
2. **Before H5 — whole-module review (opus).** Covers H2's lifecycle semantics and
   the H4 wiring.
3. **H5 — consensus review + full `./gradlew build`.** Consensus-behavior changes
   need the whole graph (the E2E cluster tests), not a module-scoped build.

A `code-reviewer` (opus) pass also runs between every phase.

## Phases as sub-issues

Eight sub-issues. One implementer worker per sub-issue; invariant tests of design
§10 land **with** (never after) their phase.

| Sub-issue | Phase | Module / new deps | Gates | Risk |
|---|---|---|---|---|
| H1a | Ledger lattice | new `:kuilt-heddle`, `:kuilt-crdt` | H1b | high |
| H1b | Entitlement economics | `:kuilt-heddle` | H2, H3 | **highest** — conservation |
| H2 | Lifecycle + strict reconfiguration | `:kuilt-heddle` | H4 | medium |
| H3 | Policy (pure) — *∥ H2* | `:kuilt-heddle`, no fabric | H4 | low–medium |
| H4 | Node (Seam + Quilter + demand + liveness) | +`:kuilt-quilter`, `:kuilt-liveness`, `:kuilt-core` | H5 | medium |
| H5 | Control plane (Raft mint + topology serialization) | +`:kuilt-raft` | H6 | medium |
| H6 | Warp lane integration | new `:kuilt-warp-heddle` satellite | — | low–medium |
| H7 | Polish pass (audit / testing 2nd pass) | all | — | low |

### H1a — Ledger lattice

Module scaffold (`kuilt.kmp-library`, all targets, `us.tractat.kuilt.heddle`
namespace, **`module.md` + real KDoc landed with the module** — the Dokka
module-doc check is required on any `.kt` change, and a missing `module.md` fails
silently), identifiers (§2), checked-arithmetic helpers, `AttachmentRecord` (§3),
three-`GCounter`-per-edge accounting, `EdgeSummary`, `piece`, and the
**serializers** (`Quilter` replication in H4 needs them; every zoo type ships
them — discover this now, not in H4).

- Acceptance: `Quilted` lattice laws pass the standard zoo property suite
  (idempotent/commutative/associative, cross-order structural convergence);
  overflow paths fail deterministically (§10.12, §10.2). A merging-but-inert
  lattice is a fine intermediate state for an unpublished experimental module.

### H1b — Entitlement economics (highest risk)

`holdings(P, r)` derivation, `delegate`/`release`/`transfer`/`spend` as balanced
increment pairs in one lattice (design §4.2–4.3), `validate()` for slot-integrity
conflicts (§4.6). Topology is *static* here (fixed at `bootstrap`); lifecycle is H2.

- Acceptance: conservation identity `minted = Σ holdings + Σ spent` (no earmarks
  yet — the **full** §10.1 identity with earmarks gets its test in H4; do not mark
  §10.1 "done" at H1b) holds across randomized mutator sequences;
  `spend`/`delegate` past `holdings(P, r)` returns `null`, state untouched;
  projection homomorphism (§4.5 / §10.8) pinned. **→ ledger spec-conformance gate.**

### H2 — Lifecycle + strict reconfiguration

The lifecycle max-register (`PREPARED < ACTIVE < CLOSING < RETIRED`, join = max),
`prepare`/`activate`/`close`/`retire`, the drain discipline, derived tree-validity
with topology conflict reports (§5.1–5.3). Acceptance: design §15 Phase 2 (closure
dominance §10.10; `retire` refused until `outstanding == 0`; two-active-inbound
conflict converges to the same report on every replica with delegation refused
§10.11; reparent/weight-change end to end, old-generation history unchanged).

*Note (shared-module hazard):* H2 and H3 land concurrently in one new module and
may both touch its build file or a shared `internal` helper — the semantic-cross-PR
class. Each brief carries a one-line pointer to the other's PR.

### H3 — Policy (pure; ∥ H2)

`HeddlePolicy.pick(...)` — a pure EEVDF selection: candidates, weighted-mean parent
virtual time, eligibility, deadline, deterministic tie-break, neutral init, the wake
clamp, cross-multiplication comparators (design §7). No fabric, no I/O.

- **Inputs come from H1, not H4.** §7 consumes `EdgeSummary` **plus** the attachment
  metadata (`weight`, `initialVirtualTime` from `AttachmentRecord`) **plus** the
  `Demand` value type (§6). H1a defines `AttachmentRecord`/`EdgeSummary`; the pure
  `Demand` data class is defined **here in H3** (or H1) — never deferred to H4, or
  the H2∥H3 parallelism breaks. Enrich the policy input to carry the attachment
  metadata (pair `EdgeSummary` with its `AttachmentRecord`, or widen `EdgeSummary`).
- Acceptance: continuously demanding siblings converge to weight ratio in committed
  service; hoarder throttled; returner recovers (§7.3); neutral-creation and
  no-idle-credit (§10.5–6); exact-rational oracle model-check. **Cross-platform
  determinism is pinned by golden vectors in commonTest executed per target** (the
  SRA byte-parity precedent) — not a JVM-only assertion.

### H4 — Node (the join point)

`HeddleNode` over a `Seam`: `Quilter` replication of the ledger, an `EphemeralMap`
demand board (confirm the `NamedMux`/`MuxSeam` channel names `WarpNode` already
uses, or add an explicit channel), the local reservation table, liveness wiring,
the `heddleStatic` bootstrap, bound metrics (§8.2).

- Acceptance: design §15 Phase 4 — multi-peer convergence over `InMemoryLoom` under
  partition/heal/loss/dup/reorder (§10.7); deliver-N-times-history-rises-once (§4.4);
  stale-demand safety (§6); measured deviation ≤ the §8.2 bound with all three bound
  metrics exposed and consistent; crashed-peer earmarks stranded, no other holdings
  change; the **full conservation identity §10.1 with earmarks**.
- **Owns the design §13 end-to-end scenario**: `root → {tenant-a w1, tenant-b w1}`,
  dynamically add `tenant-a → {interactive w3, batch w1}`, partition two peers,
  schedule both sides, heal, converge, report the measured bound. This spans
  H2+H3+H4 capability and lands here.

### H5 — Control plane

Raft-backed mint + topology serialization, the `heddleGoverned` bootstrap, the
`readIndex()`-fenced revocation *seam* (specified, not shipped — reclamation is an
explicit later feature; **do not `closes` any reclamation issue from H5**).

- Acceptance: split-brain mint impossible (partitioned sim: at most one side commits
  a mint against a given supply); two overlapping reshapes serialize through the log,
  loser surfaces as a structured conflict; non-overlapping reshapes commit without
  contending, and **zero consensus messages appear on the spend path while
  control-plane proposals are in flight** (message-accounting form, §10.13 — not a
  wall-clock throughput claim). All consensus tests through the canonical harness
  (`RaftSimulation`/`raftRunTest`/`MultiNodeRaftSim`), tight timeouts, seeded
  election RNG — no hand-rolled network. **→ full `./gradlew build` before merge.**

### H6 — Warp lane integration (new satellite)

**Module decision (resolved):** a `Lane` type on `TaskDescriptor` would put a
`:kuilt-heddle` type in warp core's *serialized wire format*, and Gradle KMP has no
compile-time-optional dependency. So: warp core carries an **opaque** lane tag (a
warp-local value type / `String` envelope field, defaulting to a root lane so
untagged warp is bit-for-bit unchanged), and the enforcement adapter lives in a new
satellite **`:kuilt-warp-heddle`** (depends on `:kuilt-warp` + `:kuilt-heddle`),
matching the existing `:kuilt-warp-planning`/`-ml`/`-compiler`/`-runtime` pattern and
keeping warp's wire format decoupled from the experimental module.

- Work: opaque lane field on `TaskDescriptor` (default root lane), execution-side
  `reserve` in the claim path (§14.4), shared liveness/mux wiring through `WarpNode`.
  Confirm the shipped envelope + claim-path types before dispatch — the design's
  `warp.shuttle(corpus, lane = …)` is the *vision* surface; the shipped entry point
  is `Warp.shuttle(sourceOpId): Draft<ByteArray>` (`kuilt-warp/.../Warp.kt`).
- Acceptance: design §15 Phase 6 — two lanes 3:1 converge in completed tasks; the
  untagged default lane reproduces today's behavior bit-for-bit; ring placement
  identical with and without the heddle; zero consensus on the coordination-free path
  (message accounting). Satisfiable with `heddleStatic`, so it may overlap H5.

### H7 — Polish pass

Audit / cleanup, a second testing pass over delivered code, and the docs-sync
obligations for a new public primitive: the agent-cookbook symptom→primitive entry
(`docs/agent-cookbook.md`, verbatim compiled snippet) and the `kuilt-primitives`
skill routing (`.claude/skills/kuilt-primitives/SKILL.md`). KDoc/`module.md`/`@sample`
land with their phases (H1a onward), not here — H7 verifies and fills gaps. Closes
the epic.

## Dispatch strategy

- **Subagent-driven, one phase per worker.** Dispatch a `general-purpose` implementer
  per sub-issue with `isolation: "worktree"` (prefer `general-purpose` over
  `coding-partner` for isolation-worktree dispatches — the latter fell back to the
  dispatcher checkout 3/3 here), Opus by default. Claim each sub-issue with a Draft PR
  (`closes #H<n>`) before bulk work. `code-reviewer` (opus) between phases; the three
  review gates above.
- **TDD per the repo rule:** failing test first (first commit), then implementation,
  then revert-to-confirm. Invariant tests land *with* their phase.
- **Test discipline is non-negotiable** (CLAUDE.md): the canonical simulation harness
  only, tight timeouts at both the test and the agent-command layer, one convergence
  test per agent run, seeded per-node election RNG, `StandardTestDispatcher`, bounded
  awaits — never `advanceUntilIdle()`, never a hand-rolled cluster network. A hang is
  a stop-and-re-plan signal.
- **Full `./gradlew build` before auto-merge on any code PR** — `jvmTest` hides the
  Android/Native variant compile and the E2E cluster tests; H5 (consensus behavior)
  needs the full build, not a module-scoped one.
- Same experimental posture as the warp satellites: `:kuilt-heddle` and
  `:kuilt-warp-heddle` stay out of `:kuilt-bom` and `kuilt.publish` until they earn
  their way in (this also sidesteps the publish-not-in-ci-required trap new KMP
  modules have caused here).

## Risks & open questions

- **H1b is the crux.** A conservation or exclusive-slot bug in the `EntitlementLedger`
  blocks everything above it — hence the split (audit a stable lattice) and the
  spec-conformance gate right after it. Treat design §10 as the test oracle.
- **Warp's shipped `shuttle` API is not the dream surface** — H6's real integration
  point is the `TaskDescriptor` envelope field + execution-side reserve; confirm the
  exact envelope/claim-path types before briefing H6.
- **Serialization** — the ledger's `KSerializer`s are H1a's job; discovering them in
  H4 would reopen H1's shape.
- **Cross-platform determinism** — golden vectors per target (H3), not a JVM-only test.
- **`MovableTree` is a v2 temptation, not v1** — a conflicting structural move would
  strand entitlement on a vanished path; v1 stays on strict generation-and-drain.
- **Fencing/reclamation is deliberately deferred** — H5 ships the seam only; crashed-
  peer entitlement stays safely stranded until a later reclamation feature.

## Relationship to warp

`:kuilt-heddle` is independently consumable but its headline customer is the shipped
warp program (Phase-2 satellites `:kuilt-warp-planning`/`-ml`/`-compiler`/`-runtime`;
`docs/warp-roadmap.md`). It supplies the one thing warp lacks at every phase —
fairness — as the load-smoother grown into a weighted tree (design §14), wired in
through the new `:kuilt-warp-heddle` satellite.
