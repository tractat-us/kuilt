# Replication

Every device in a group might change the same shared piece of information at
once — a score, a list, a shared note — with nobody around to referee whose
change wins. These modules are what lets everyone's changes merge back into one
answer on their own, keep that answer moving between many devices without every
pair having to talk directly, fairly deal out a shuffled hand of cards that
nobody — not even the dealer — can peek at, and keep a written history beside the
live copy for later.

What a consumer is about to hand-roll, and the primitive that already exists, with
compiled snippets: `docs/agent-cookbook/replication.md`. This file holds only the
rules for changing the code here.

## Rules

- **Adding a CRDT is a four-pass pipeline, not impl-plus-tests.** Each pass is a separate dispatched
  agent branching from a stable `main` and touching only its own files, so the passes are mutually
  conflict-free and the fan-out can go wide.
  1. **Implement**, TDD, then review, then merge.
  2. **Docs** — a rich accessible-first zoo entry per type at `Writerside/topics/crdt-<type>.md`,
     following the descent shape the root `CLAUDE.md` prescribes: plain-language opener with a
     concrete example, then intuition, then mechanism, with guarantees and honest constraints last.
     One agent per topic file.
  3. **Architecture pass**, per type: DRY, idiomatic Kotlin, nullability and fail-fast, exception
     discipline, coroutine and clock creep, serialization determinism. PR only if the findings are
     substantive.
  4. **Performance and replication pass**, per type, and specifically about *how the type replicates
     over a `Seam`*: delta minimality versus full-state shipping, idempotence under `GossipSeam`'s
     eager-flood re-delivery, fingerprint and byte-stability for `GossipDedup`, causal-GC
     participation (`Quilted.causalDots()` and its bounded companion `causalFloor()`), op-log
     growth, and anti-entropy and late-join cost. Its output is a findings report plus filed
     issues — **analysis only, never source PRs**, because those would race pass 3's.

  The per-type files never collide; the shared ones do. `kuilt-crdt/module.md`,
  `Writerside/kuilt.tree` and `CrdtSamples.kt` are appended to by every type's PR at once, so
  serialize *those* merges through one agent that unions the additive conflicts, rather than having
  each worker rebase against the others.

**One requirement stands behind both rules below: identical bytes on every target.** A replicated
state is compared, deduplicated and merged by its encoding, so a value that encodes one way on the
JVM and another on Kotlin/Native is not one value — it is two, and the peers holding each have
diverged with nothing to red. `commonTest` is the single mechanism that pins it: a `commonTest`
source runs on JVM, Android, iOS, macOS and wasmJs, so a golden vector there fails the build the
moment two targets disagree, while a JVM-only round-trip test cannot see the divergence at all.
"It round-trips" is therefore never the evidence asked for here. The third face of the same
requirement — a state's serialized form being a function of its logical value alone, not of merge
order and not of platform — is the canonical-encoding invariant written up in
`kuilt-crdt/module.md`; read it before adding a type with an unordered `Map` or `Set` field.

- **Vendor one faithful implementation of a published standard — don't hand-roll a hash, and don't
  reach for a library either.** The byte-identity requirement above rules out platform-native
  hashing outright, and it rules out most libraries too: there is no suitable wasmJs-covering
  dependency at an acceptable footprint. The resolution is the third option, and it is the community
  norm rather than a local eccentricity — Guava, Redis, Cassandra and datasketch all do exactly
  this: **one** vendored, spec-faithful implementation of a *published* algorithm, shared by every
  type that needs it. Here that is `Murmur3` (canonical MurmurHash3_x86_32, `:kuilt-crdt`,
  `us.tractat.kuilt.crdt.internal`), shared by `HyperLogLog`, `BloomFilter` and `CountMinSketch`
  since #740 — which replaced three divergent hashes, one of them a seeded LCG with no avalanche
  at all. A new sketch type uses it; a genuinely new primitive follows the same shape rather than
  growing a second hash beside this one.

  **The gate on a vendored primitive is golden vectors verified canonical rather than merely
  self-consistent, plus full condition and branch coverage** (`kover` is applied at the root).
  Self-consistent vectors are the trap: generated by running the implementation, they pin whatever
  it does *including whatever it does wrong*, and the build then stays green through a
  faithful-looking re-derivation that is not the published algorithm. `Murmur3Test` pins against the
  smhasher reference across every tail length, a multi-block body, non-ASCII UTF-8 and non-zero
  seeds. The gate is load-bearing, not ceremony: the pass that brought it to `CountMinSketch` (#722)
  is the pass that found that type's `width`/`depth` validation sitting in `empty()`, which
  kotlinx-serialization bypasses — every wire-delivered sketch had been skipping it, and moving
  the `require`s into an `init` block is what made them fire on decode. That is the wire-type rule
  `.claude/rules/fabrics.md` states, reached here by an exhaustive-coverage pass rather than by
  review.

- **A new modular-arithmetic path canonicalizes its bytes before they reach the wire, and pins
  golden vectors in `commonTest`.** `:kuilt-deal` compares SRA ciphertext by **raw bytes** —
  `CardState.equals` uses `contentEquals`, and `CardState.merge`'s tie-break sorts by byte order —
  so two peers encrypting the same card must produce byte-identical output or cross-platform play
  diverges silently: a JVM peer and an iOS peer disagree about the deck, with nothing raised
  anywhere. The concrete trap is `java.math.BigInteger.toByteArray()`, which emits a leading `0x00`
  two's-complement sign byte whenever the high bit is set, while the ionspin big-integer used on
  iOS, macOS and wasmJs can differ again. #385 took the native `modPow` fast path on JVM/Android
  (~40× faster) and paid for it with `sraModPowCanonical`, whose `canonicalMagnitude` strips
  leading zero and sign bytes so every path encodes the same integer to the same minimal big-endian
  magnitude — re-parsing a canonical magnitude with positive sign is lossless, so stripping is
  safe. A second `CommutativeScheme`, a ZK-proof path, or ciphertext persistence inherits the
  obligation whole. Pin the vectors in `commonTest` for the reason stated above, and **include a
  high-bit case** — `SraModPowTest.goldenVectorsAreCanonicalAndPlatformIndependent` uses
  `3^5 mod 251 = 0xF3` — or sign-byte stripping is never exercised and the vectors pass over a
  step that did nothing.
