# kuilt primitives — check before you build

kuilt almost certainly already provides the networking / session / shared-state
thing you're about to write. **Before hand-rolling, read the cookbook** and use the
primitive it names.

## Where the cookbook is

Read the first path that exists, in order:

1. `docs/agent-cookbook.md` — if you are working inside the kuilt repo.
2. `../kuilt/docs/agent-cookbook.md` — if kuilt is checked out side-by-side
   (the `includeBuild("../kuilt")` layout).
3. Otherwise the source-of-truth blob:
   `https://github.com/tractat-us/kuilt/blob/main/docs/agent-cookbook.md`.

## The reflex

If you're about to write any of these, STOP and open the cookbook:

- a rejoin / reconnect / resume-token loop after a drop, or a "hold the seat open" grace window on the **joiner** side → `Room.resumeToken` (save it once admitted; `null` means this room opts out of resume) + `Room.resume(token)`. Don't re-track the window yourself. The route deleted in #1575 named `SeamRoom`, and the cookbook still does — but that class is `internal`: `SeamRoomFactory` builds it and `Room` is the whole public surface
- that same grace window on the **host** — a `pendingSeats` / `disconnectedAt` map, your own expiry timer → `JoinerReconnectController` (`us.tractat.kuilt.session.partition`): `onPeerUnresponsive` opens the window, `onPeerRecovered` closes it when the peer comes back without a token, `tryResume` validates the returning peer's `ResumeToken`, `events` reports `WindowOpened`/`Resumed`/`WindowExpired`. A `SeamRoom` host already wires one — reach for it directly only when you own the host loop
- a reconnect banner, or a "why did we drop" classifier bucketing transient vs. unrecoverable → `MembershipEvent.Partitioned.reason` (`ReconnectReason`) + `HostLost.reason` (`FailureReason`), plus the `localFabric` tag on each. Don't string-match the message
- a heartbeat / idle-reaper / "is this peer still alive" timer → `HeartbeatPartitionDetector`
- a `delay(timeout); if (peers.size < 2) close()` reaper for a room/table nobody joined → `SoloDeadlineDetector`
- a "paused / reconnecting…" flag or a `lastSeen` map for greying out a player → `Room.roster` + `Member.liveness` (the level; `Room.events` is only the notification)
- that same "paused / reconnecting…" surface for a **game** rather than a bare room, a `room.events` → game-presence adapter → `gameOverRoom(room)` → `RoomGameSession.presence`/`roster` (`:kuilt-game`), which *are* `room.events` and `room.roster`. It owns the room — tear both down with `RoomGameSession.close`, never `room.leave()`. Presence here is **link** liveness, so layer human "seated / away" on top
- a countdown on a reconnecting peer — "how long until their seat is released?" → `Liveness.Partitioned(since, windowExpiresAt)` read off `Room.roster`, never an event replay
- a "you're offline" / "your connection dropped" banner, telling *your* outage apart from *theirs*, "am I the one offline?" → `Room.localFabric` + `MembershipEvent.LocalFabricLost`/`LocalFabricRestored`, plus the `localFabric` tag on `Partitioned`/`HostLost`
- a per-game / per-session id every peer must agree on — keying a durable `(session, device) → seat` record, scoping a log, naming a table, "mint a game id and replicate it over a channel" → `Room.roomId`, already agreed in the admit handshake. **Not** the host's peer id, which names the *device* and repeats across every room it hosts. `null` on a joiner means *not admitted yet*, so collect it rather than sampling it. When the identity is decided *outside* kuilt — a lobby code, an invite link, a matchmaker-assigned game id — pass it in as `RoomFactory.host(pattern, roomId = …)` and every member reads that value back. It does **not** make a *host restart* resumable (no roster, no window registry on the new host) — that's #1593
- a propose→authoritative/rejected turn or session facade, host election with a term → `GameSession` + `TurnSequencer`
- branching on why a rejoin was refused — "was that the grace window elapsing or a bad token?", "should I retry or re-join fresh?" → `Room.resume` returns `ResumeResult.JoinerOutcome`: `Refused(message, code)` is the host's answer and **`code.retryable` is the decision** (`ResumeWindowNotYetOpen` is transient — retry; an elapsed window or an invalid token is not). `TimedOut` is silence, `WindowClosed` means your room is already over and never asked. The host-side verdicts (`WindowNotYetOpen`, `TokenInvalid`) are a different half of the hierarchy and cannot reach a joiner — branching on one is a compile error
- picking a host among already-connected peers before any room exists, "who hosts", a `host == selfId` check → `SeamRoomFactory.electLobby` → `ElectionLobby`. `awaitRoom()` returns a sealed `ElectionOutcome`: `Adopted(room)`, `Torn(reason)` (a real mid-2PC collapse, retryable via `electLobby`), and `BecameHost` — the peer that was hosting left, so **you** are the elected host now. The recovery for `BecameHost` is `start()` on the **SAME** lobby: the co-members are still parked on the same seam. Re-running `electLobby(...)` weaves a fresh seam and strands them; `leave()` first collapses them. `host == selfId` alone is **not** a promotion — during weave-in you are transiently the lowest id you can see
- a last-write-wins register, grow-only set/counter, add/remove set, "merge two states" → the CRDT zoo, by name: `LWWRegister` / `LWWMap`, `GSet` / `GCounter` / `PNCounter`, `ORSet` / `ORMap`, `BoundedCounter`, `Causal`, and `EphemeralMap` for per-peer presence slots that age out on a TTL (`:kuilt-crdt`)
- a shared **JSON document** — nested objects/arrays/scalars edited concurrently, a collaborative config or metadata blob → `JsonCrdt`. `set`/`remove` return a `Patch` carrying one key, so an edit costs the same however large the document is; hand it to `quilter.mutate { it.set(key, node) }`, or absorb it locally with `doc.piece { it.set(key, node) }`. A change *inside* a nested object still rebuilds that object, so that frame is the size of the subtree (#2469)
- a shared list/log that only ever grows — "keep the last N entries", trimming a chat backlog or an on-device buffer, "removing entries doesn't free anything", an entry that comes *back* after a merge → `Rga.dropWindow` (and read `causalFloor()` with `causalDots()` if you fold your own frontier)
- an audit trail / archive of a shared list that must survive what the replica forgets — "keep a year of history on the server beside an hour on the phone", "compaction on one peer wiped history on another", wanting the *edits* rather than the current value → `OpLogCrdt` (`operations()`/`classify()`/`dotOf()`; keep `LogOp.Insert`+`Remove`, discard `LogOp.Compact`). Never by merging — `piece` makes forgetting contagious
- **wiring** that archive up rather than hand-rolling the tee — "records a peer gossiped to us vanish when that peer forgets them", "my archive only has my own history", a duplicate copy of a peer's log per anti-entropy round → `BoltDecorator` (`:kuilt-bolt`) fed by `WarpLogRecordExporter(appliedOps = …)` (`AppliedOpSink`, `:kuilt-otel`), or by any other `Rga`/`Fugue` owner. **Publish on the merge path too** — a merge is a state join with no ops to tee, and gossip is how another device's records arrive, so a local-only tee archives nobody else's history. Suppression of re-offered ops is the decorator's job: inserts are suppressed from a dot frontier costing one entry per author rather than one per op — bounded in **runs** by `frontierWindow` (one per author, plus one per unfilled hole; past it the shortest run is evicted and its inserts are archived twice) — and removes from a bounded LRU window (`removalWindow`) because a remove mints no dot; a failed append reports the lost **dots** on `BoltDecorator.health`, never a count
- **reading** that archive back — "replay what the phone compacted away", "did I get the whole history or did it stop somewhere?", "is my archive intact", a resume cursor over an append-only log, "can I trim the live copy yet?" → `Bolt.replay(scope)` + `ReplayScope` (`:kuilt-bolt`). **Collect to completion**: the terminal verdict (`CleanTail`/`Truncated`) is the only thing distinguishing a whole history from one that stopped at damage, and `take`/`first`/`.frames()` discard it. `TruncationReason` splits on the *remedy* — `SegmentHeader`/`Frame` mean "not readable yet, resume later"; `MissingRegion` means gone. Resume only from a **cursor** (`All`/`FromOffset`), never from `Arrived` or `InsertsAbove`, and ask `Bolt.durability()` before trimming the live replica's own window
- replicating a CRDT over a connection by hand → `Quilter`
- a conditional write to shared state — "claim the seat only if it's free", "publish only if nobody already did" — or a no-op/identity patch standing in for "I decided not to write", or a `var applied = false` captured out of a `mutate {}` → `Quilter.mutateOrSkip { … }` (return `null` to decline; it answers whether anything was published)
- a forwarding hop through the host so two guests can reach each other — "peer B never sees peer A's updates", "the Quilter between two joiners never converges", "this peer is in the roster but every send to it fails", messages that reach the host and stop → `Room.channel(id)`; the room relays already (run replicators over the room's channel view, never over the raw fabric `Seam`)
- averaging model updates from many devices without collecting their data — federated learning/analytics, a `(Σweights, Σcount)` accumulator, a training-round barrier → `FedAvg` + `TrainingUpdate`
- hashing a replicated state by hand so two peers can compare it as one number — "are we in sync?" across a process/socket boundary, a divergence alarm → `canonicalDigest` (and in-process, just `assertEquals` the states)
- splitting a big blob into frames, hard-coding a chunk size, or chasing a `FrameTooLargeException` that shows up only once a peer drops out → `Room.maxPayloadBytes` / `Seam.maxPayloadBytes` (`null` means unknown, not unbounded). Past the budget an addressed `sendTo` raises `PayloadTooLarge`, which names the budget you could have read; `broadcast` is lossy-without-error by contract and drops the frame with a log
- looping a frame back to yourself, or a `peers.forEach { sendTo(it, …) }` fan-out — `peers` **includes** `selfId`, so that self-sends → `broadcast`, or filter `it != selfId`. `sendTo(selfId, …)` throws `IllegalArgumentException` on every fabric (not `PeerNotConnected` — you *are* in `peers`)
- a `seenIds` set → `GSet` / kuilt dedup
- a fixed/exponential retry back-off → `ExponentialBackoff`
- merging mDNS/Multipeer discovery feeds into one lobby roster → `discoveryRoster`
- a sweeper or `lastSeen` timeout over that lobby list because peers accumulate and are never removed — someone left and their name is still on screen → the removal already exists: `discoveryRoster` drops a peer when a source emits its `Tag.peerKey` from `PeerDiscoverySource.departures()`. There is **no interface default**, so a source with no leave signal has the `emptyFlow()` written out — read each one and you can see which of yours the ghost caveat covers. If you own the source, fix `departures()` and bind it to `DiscoverySourceConformanceSuite` (`DepartureFixture.Emits` / `NoLeaveSignal` — the second arm is a claim the suite checks, not an exemption). Emitting *something* is not enough: the roster removes by exact key, so a display name or a socket address leaves the same ghost while looking right in a log
- **writing a fabric** and about to turn a peer-supplied id into membership — `PeerId(bytes.decodeToString())` into a `Set<PeerId>` a callback adds to and removes from → `PeerIdentityRegistry` (`:kuilt-core`). Key by the **device identity**, not the bare id: `bind` returns `COLLISION` (a second device on one id is refused, the incumbent keeps it), `REFUSED_SELF` (a peer handed its own advertisement) and `REFUSED_BLANK`; `unbind(id, token)` is identity-scoped so a drop can only remove the device that actually holds the id; `clear()` at teardown. Derive the roster from `registry.peers + selfId` and end the session on `registry.peers.isEmpty()` — **not** on `peers == setOf(selfId)`, which one blank id makes unsatisfiable forever. Decoding is still yours: `decodeToString()` is LOSSY, so decode with `throwOnInvalidSequence = true` or two different announcements arrive as one id
- a weighted / fair-share scheduler, "give this group 3× the share", "who runs the next quantum", an EEVDF/weighted round-robin → `HeddlePolicy.pick` + `HeddleNode`
- an entitlement/quota/budget ledger, "reserve a slot before running then charge once", a coordination-free budget that converges across peers → `EntitlementLedger` + `HeddleNode.reserve`/`complete`
- minting quota or re-parenting a group at runtime with everyone agreeing on the order (no double-mint on a split) → `heddleGoverned` (`GovernedHeddleNode`)
- gating a `WarpNode`'s tasks by a weighted lane ("interactive gets 3× batch") → `HeddleAdmissionControl` + `TaskDescriptor.inLane`
- "only run on GPU/in-region peers", a placement predicate over peer capabilities, "can this peer run this" → `Affinity` + `TaskDescriptor.where` + `CapSet`
- a blob cache keyed by a content hash, a "have you got these bytes?" request/response, a manifest of what each peer holds → `Creel` + `BobbinExchange`
- running code that arrived from another peer — a plugin loader, an `eval`, a bespoke sandbox or timeout-and-kill wrapper → `WasmRuntime` + `WasmSandboxConfig` + `WarpLazyFetch`
- a flush-per-line loop in a log/telemetry exporter, or a fix for "capturing logs is slow" / "the app stalls when it logs a lot" → `WarpLogRecordExporter.export(records)` (a run of records is one write turn, with the durability contract unchanged) + `installLogCapture` (already drains into it in batches)
- emptying a telemetry store — "reset the logs", "clear my data", "start the next run clean" — by deleting its files per platform, or a "clear on next launch" flag so the delete lands before recovery → `WarpTelemetry.clear()` (`:kuilt-otel`), or a single signal's own `clear()`. It runs on a **live** instance, and logs/spans *suppress* what they drop so a peer holding the old ops cannot push them back through a merge (metrics can only forget locally)
- a flag or counter of your own tracking whether telemetry is still being written — "has anything landed since launch?", "are we losing log lines?" → `WarpLogRecordExporter.health` (`ExporterHealth`, with `isDead` already derived) and `LogCaptureInstallation.health` (`CaptureHealth.droppedEvents`). Both are `StateFlow`s. Drops climbing while the exporter is healthy means the export path works and is simply too slow for this log volume
- stamping which session/game/request a log line belongs to — an MDC equivalent, a "logger context", or a mutable global holding "the current session" that a log mapper reads → `withLogContext(attributes) { … }` (`:kuilt-otel-logging`), **not** `CaptureConfig.attributeMapper`. The mapper is installed once per **process**, so an app running two sessions at once stamps the second one's lines with the first one's id and nothing downstream can tell — resolving it at the edge fixes *when* it is asked, not *which* session it can see (#1659). Keep the mapper for genuinely app-wide facts (device, build, logger name). Precedence is **narrower scope wins**: mapper < outer `withLogContext` < inner, and nesting merges rather than replaces. Reach is the same as `withActiveTrace` — hop-safe and inherited by child coroutines on JVM/Android, synchronous-within-the-block on iOS/macOS/wasm
- saving bytes so they outlive the process — a write-temp-then-`fsync`-then-atomic-rename dance, an `expect`/`actual` file helper per platform, an IndexedDB wrapper, "did that write land before we crashed?" → `DurableStore` + `StoreKey` (`:kuilt-store`), with `InMemoryDurableStore` in tests and `FileChannelDurableStore` / `NSFileManagerDurableStore` / `IndexedDbDurableStore` in production. The contract is a **timing** one — `write` returns only once the bytes are committed — so a caller may report its own success there. It is deliberately small: no iteration, no query, no cross-key transaction. Want replayable history instead? `Bolt` (`:kuilt-bolt`). Want state that merges across peers? the CRDT zoo

Then follow the cookbook's exact primitive and snippet.
