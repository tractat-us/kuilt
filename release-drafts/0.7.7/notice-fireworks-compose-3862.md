kuilt [v0.7.7](<v0.7.7 release link>) gives L5 a third answer to "device id or account id?": a **device key** (tractat-us/kuilt#3159). It is stable across every surface a device reaches, and a peer can check it.

Each device keeps one P-256 key in `DeviceKeyStore.platform(…)`: the Keychain on iOS, the Keystore on Android, a non-extractable WebCrypto key on wasm. A room member proves it on every join. Give the nw and server factories the same store, and `Member.key` is the same `DidKey` in both rooms. `DeviceIdStore` stays f-c's own id, as ruled: pass it as `join(…, deviceId =)` and the key signs over it, so `Member.identity.deviceId` is bound to `Member.key`.

What that buys L5, and what it doesn't:

- **One device, N reaches: yes.** Merge `LobbyPlayer` rows on the key. Ranking `Nw` over `WebSocket` still needs the per-seam liveness from the 2026-07-30 comment; 0.7.7 adds none.
- **A key in `LobbyPresence` is still only a claim.** Presence is f-c's CRDT, not a kuilt roster. Trust it only once it matches a `Member.key` the room checked, or sign the entry with `DeviceKey.signApp("fireworks/presence", entry)` and check it with `DidKey.verifyApp`. The raw `DeviceKey.sign` is internal to kuilt now, so an app signature can never pass for one of kuilt's own.
- **One person: no.** A person with two devices has two keys. Linking them is later work in kuilt, so the account stays the person-level id.
- **Keys aren't unique per row.** Two wasm tabs share one key and hold two seats; dedupe for display, not for routing.

**Upgrade every peer of a room in one step.** The admit wire goes from version 2 in 0.7.6 to version 9 in 0.7.7, and each side accepts only its own. A 0.7.7 server refuses a 0.7.6 app with `ProtocolMismatch`, and a 0.7.6 server refuses a 0.7.7 app. Shipped App Store builds can't join an upgraded server, and an upgraded build can't join an old one, so the server deploy and the app release have to go out together, with a plan for the builds already installed.

What else the upgrade touches in f-c:

- `RejoinCoordinator`'s and `ResumableGame`'s KDoc say a cold start "cannot present a kuilt `ResumeToken`". From 0.7.7 there is no token at all: `Room.resume`, `Room.resumeToken` and `ResumeToken` are gone. A restarted device gets its held seat back by its key, within 60 s, and inside its pass (an hour after last contact under `AdmissionPolicy.open()`, sometimes up to 90 minutes) it skips vetting. Both need a platform store, not `InMemoryDeviceKeyStore`.
- f-c's own `Room` fakes (`FakeRoom`, `FakeMembershipRoom`, `DelegatingMembershipRoom`) drop their `resume` and `resumeToken` overrides and take the new `host(…, admission)` and `join(…, deviceId)` shapes.
- A `when` over `MembershipEvent` or `LeaveReason` meets `Readmitted`, `Superseded(by)` and `Unobserved`, and `Joined` gains `returning`.
- f-c pins `0.7.0-dev.1700`, so the jump takes in 0.7.1–0.7.6 too. The migration steps are in the release notes.
