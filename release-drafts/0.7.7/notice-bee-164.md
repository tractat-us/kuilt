kuilt [v0.7.7](<v0.7.7 release link>) gives this menu its "per-device" half, so the identity work the 2026-11-09 comment waited on has landed (tractat-us/kuilt#3159). It does not give the menu its actions. Here is what each one can stand on:

- **Evict.** Each peer bubble's `Member.key` is that device's proved key. `HostAdmission.revocations.revoke(key, notBefore = now)` voids every pass that device holds, so it can't walk back in unvetted. A revoked device that is still connected keeps its seat, but its pass stops being renewed. **Three things kuilt leaves to bee.** Revoking removes nobody present, and kuilt has no "remove this member" call, so dropping someone from the strip is bee's. A revocation is permanent, so keep an undoable blocked set and refuse it in bee's `AdmissionPolicy`. And use a durable `RevocationList.open(store)`, or a restart forgets every eviction.
- **Make host.** Not in kuilt. Roles stay bee's, and the host enforces them. Note that a pass works only with the host that issued it: another peer taking over as host does not inherit those passes, and returning people are vetted again.
- **Evicting a person's agents.** A kuilt key belongs to a key store, not to a person. An agent that opens its own store has its own key, so "the agents joined with that person's device key" needs bee to record which agent keys came in under which person. An agent that opens the person's store shares their key, and then the host cannot tell the two apart. kuilt can't link keys yet (personas come later).
- **`--forget-devices` becomes optional:** revoke one key instead of every one.

The upgrade itself is the lockstep one #149 describes: the host, every page and every agent move to 0.7.7 together.

So the open design calls here are still open, but each can now act on a proved key instead of the network path.
