kuilt [v0.7.7](<v0.7.7 release link>) ships the first slice of the identity work this issue waits on (tractat-us/kuilt#3159). It covers the **anonymous, self-carried** bullet. It does not cover SSO or OAuth.

Every device now keeps a P-256 key that never leaves it, named by a `did:key`. A member of a kuilt `Room` proves that key when it joins, and the host sees it as `Member.key` and `AdmissionRequest.key`. While the member stays, the host hands it a signed pass. A device that drops and comes back is let back in with no code in bee: into its held seat within 60 s, even after a restart, or past the policy within its pass (1 h by default). A pass with `GrantReach.AnyRoomOfIssuer` also survives a host restart, if the host keeps its key in `DeviceKeyStore.platform(appId, dataDir)`.

What it means for bee:

- **Only the claims room gets it.** `KtorRoomHost` on the claims path is a kuilt `Room`; the board's `KtorConnectionSource` and HTTP-joined agents are not. #159's kept identities stay bee's until those ride a `Room`.
- **Two things named `DeviceKey`.** bee's is a bearer string a link or pairing hands out; kuilt's is a private key no peer ever sees. Decide whether bee's pairing turns into "admit this `DidKey`", or the two stay apart. Either way, rename one in bee's code.
- **"Roles come from identity"** has its hook now: an `AdmissionPolicy` decides on a proved key, and bee keeps the role table.
- **Breaking upgrade.** Every host, page and agent moves to 0.7.7 together; older peers get `ProtocolMismatch`. The migration list is in the release notes. bee pins `0.7.0-dev.1696`, so the jump also takes in 0.7.1–0.7.6.

Not met: SSO, OAuth for remote MCP clients, a pluggable identity provider, and linking one person's devices (personas are later in tractat-us/kuilt#3159).
